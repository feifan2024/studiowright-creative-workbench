01

接入准备

先连接工作台，再读取真实可用的账号、项目与模型。

访问与密钥

先在上方创建统一密钥。地址中的 127.0.0.1 指运行调用程序的电脑；Windows 需保持工作台的 SSH 转发，Ubuntu 本机使用同一地址。统一接口不是 OpenAI 兼容接口，不要直接开放到公网。

每次请求在 Authorization 请求头中携带 Bearer 加密钥。所有密钥均有读取和生成权限；管理页面及工作台端口只供可信本机使用。Flow 原后台保留自己的独立密钥。

Python 公共准备

以下示例使用 Python 标准库。先把创建的密钥设置为环境变量 STUDIOWRIGHT_API_KEY，再将公共准备与需要的示例放在同一脚本中。只复制或浏览本页不会发起请求。

Windows PowerShell 可以输入 $env:STUDIOWRIGHT_API_KEY = Read-Host '输入统一密钥'；Ubuntu 终端可以输入 read -s STUDIOWRIGHT_API_KEY; export STUDIOWRIGHT_API_KEY 后输入密钥。只在可信环境中使用。

Python · 放在脚本开头
import json
import os
import uuid
from pathlib import Path
from urllib.request import Request, build_opener, ProxyHandler
from urllib.error import HTTPError

BASE = "http://127.0.0.1:18922"
API_KEY = os.environ["STUDIOWRIGHT_API_KEY"]
client = build_opener(ProxyHandler({}))

def call(path, payload=None, request_id=None):
    headers = {"Accept": "application/json", "Authorization": "Bearer " + API_KEY}
    body = None
    if payload is not None:
        body = json.dumps(payload, ensure_ascii=False).encode("utf-8")
        headers["Content-Type"] = "application/json"
        if request_id:
            headers["Idempotency-Key"] = request_id
    request = Request(BASE + path, data=body, headers=headers)
    try:
        with client.open(request, timeout=180) as response:
            return json.load(response)
    except HTTPError as error:
        try:
            detail = json.load(error).get("error", "请查询原请求记录")
        except (ValueError, AttributeError):
            detail = "请查询原请求记录"
        raise RuntimeError(f"请求失败（HTTP {error.code}）：{detail}") from error

Gemini 对话与推理

通过账号池进行官方文字对话；结果异步保存，可查询原请求。

POST/api/real-pool/chat官方调用已接入 · 返回排队记录，不重复提交
官方文字调用 · 账号池轮询

先创建对话，再提交一次消息。自动账号使用 auto；同一对话后续始终使用首次账号。并发上限可设为 1～5，超出排队；暂停、授权未就绪或结果待核对的账号不参与自动派发。

提交超时先查询原请求编号；不要重新提交新编号。当前对话接口只收文字，不使用网页或自动换号回退。

Python · 创建、发送并查询结果
import requests, uuid, time
base = "http://127.0.0.1:18922"
import os
headers = {"Authorization": "Bearer " + os.environ["STUDIOWRIGHT_API_KEY"]}
chat = requests.post(base + "/api/conversations", headers=headers,
    json={"title": "我的官方对话"}, timeout=20).json()
request_id = str(uuid.uuid4())
print("请保存本次请求编号:", request_id, flush=True)
result = requests.post(base + "/api/real-pool/chat",
    headers={**headers, "Idempotency-Key": request_id},
    json={"account": "auto", "conversation_id": chat["id"], "prompt": "你好"}, timeout=30)
result.raise_for_status()
for _ in range(300):
    record = requests.get(base + "/api/real-pool/requests/" + request_id,
        headers=headers, timeout=20).json()
    if record["status"] not in ("queued", "dispatching", "running"):
        print(record)
        break
    time.sleep(2)
# 继续此对话：使用原 chat["id"]、新 request_id、新 prompt。
# account 可仍填 auto，系统会固定首次账号；不会重新轮询。
# 只查询原请求，不在超时或失败时自动重发。

查询提交与生成结果

先用请求编号查询工作台记录。submitted 仅表示已经交给 Flow 排队；再使用返回的 task_id 在快照的最近任务中查找执行状态和 downloads。快照仅包含最近 150 条任务。

Python · 查询已提交的任务
record = call("/api/real-pool/flow-requests/" + request_id)
print("提交记录:", record)
if record.get("task_id"):
    state = call("/api/snapshot")
    tasks = [t for t in state["tasks"] if t["source_id"] == record["task_id"]]
    print("原任务:", tasks)  # 可能包含状态、关联重试和 downloads

任务成功后，使用返回的 downloads[].path 加统一 API 地址和同一把密钥下载文件。列表为空代表暂时没有可下载文件。

Python · 下载已完成的文件
download_path = tasks[0]["downloads"][0]["path"]
request = Request(BASE + download_path, headers={"Authorization": "Bearer " + API_KEY})
with client.open(request, timeout=180) as response:
    Path("生成结果").write_bytes(response.read())
04

接口与状态

查询不等于重新提交；超时也不等于任务没有执行。

接口作用
GET /api/health工作台健康状态。
GET /api/snapshot读取当前账号、项目、模型及最近任务。
POST /api/conversations创建对话；字段 title。
GET /api/conversations/{id}读取该对话与消息记录。
POST /api/real-pool/chat提交一次官方文字消息；返回 queued，使用原请求编号查询。
GET /api/real-pool/requests/{请求编号}查询一次 Gemini 请求与回复。
POST /api/real-pool/flow提交图片或视频生成。
GET /api/real-pool/flow-requests/{请求编号}查询 Flow 的提交记录和原任务编号。

查素材与下载

GET /api/library?page=1&limit=24 列出已入库素材；GET /api/library/{素材ID} 查看单项，GET /api/library/{素材ID}/file 下载原文件。基础分类在 structured_tags，已有的拍摄角度、运镜等补充标签在 shot_tags（可能没有）。Gemini 镜头说明及补分析入口在工作台素材详情，统一密钥接口不开放补分析或密钥管理。

每条新请求使用新的 UUID；同一次请求需要保留原编号和原始参数。遇到超时、断线或 unknown 时，先查原记录与关联任务，不要换编号重复生成。账号或对话尚未核对、参数不正确时，读取返回的 error 并处理。
